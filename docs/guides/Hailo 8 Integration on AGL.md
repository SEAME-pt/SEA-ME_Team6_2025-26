## HailoRT & Kernel Integration

### Overview

The Hailo-8 (26 TOPS) connects to the Raspberry Pi 5 via PCIe and is accessed through two distinct layers:

| Layer | Component | Version |
|-------|-----------|---------|
| Kernel space | `hailo_pci.ko` driver | Built against kernel `6.6.63` |
| User space | HailoRT runtime + Python API | 4.23.0 |

On AGL, the PCIe device is recognised at boot:

```
0000:01:00.0 Hailo Technologies Ltd. Hailo-8 AI Processor
```

### Critical issue: 16K page kernel incompatibility

The default AGL kernel for RPi5 is compiled with `CONFIG_ARM64_16K_PAGES=y`, producing a kernel identified as `6.6.63-v8-16k`. The Hailo-8 PCIe driver calculates DMA descriptor sizes based on the kernel page size. With 16K pages, the descriptor size exceeds what the RPi5 PCIe controller can map, making the driver non-functional.

Confirmed via:

```bash
getconf PAGE_SIZE
# 16384  ← incompatible with Hailo-8
```

The fix is to rebuild the kernel with `CONFIG_ARM64_4K_PAGES=y` via a Yocto kernel fragment in `meta-seame`.

### Yocto build-level fix

**Kernel fragment** — forces 4K pages:

```
# meta-seame/recipes-kernel/linux/linux-raspberrypi/seame-hailo-pagesize.cfg
# Hailo-8 requer 4K pages - incompativel com 16K pages
CONFIG_ARM64_4K_PAGES=y
# CONFIG_ARM64_16K_PAGES is not set
# CONFIG_ARM64_64K_PAGES is not set
```

**Kernel bbappend** — applies the fragment:

```bitbake
# meta-seame/recipes-kernel/linux/linux-raspberrypi_%.bbappend
FILESEXTRAPATHS:prepend := "${THISDIR}/${PN}:"

SRC_URI:append = " file://disable-hailo.cfg"
SRC_URI:append = " file://seame-hailo-pagesize.cfg"
```

A second fragment, `disable-hailo.cfg`, disables the in-tree kernel Hailo driver so the external module from `meta-hailo` is used instead:

```
# meta-seame/recipes-kernel/linux/linux-raspberrypi/disable-hailo.cfg
# Disable kernel-built hailo driver - using external module from meta-hailo
# CONFIG_MEDIA_PCI_HAILO is not set
```

After rebuilding (`bitbake linux-raspberrypi`), the kernel string changes from `6.6.63-v8-16k` to `6.6.63-v8` and `getconf PAGE_SIZE` returns `4096`.

### Packaging the hailo_pci driver

The `hailo-pci` recipe from `meta-hailo` (`hailo-pci_4.23.0.bb`) compiles the PCIe kernel module from the [hailort-drivers](https://github.com/hailo-ai/hailort-drivers) repository. It inherits the `module` class and builds `hailo_pci.ko` against the staging kernel directory.

The original recipe's `make install` step calls `depmod.sh` without the required `kernelrelease` argument, causing `do_install` to fail. The `hailo-pci_%.bbappend` in `meta-seame` fixes this by overriding `do_install` and setting `KERNELRELEASE` explicitly:

```bitbake
# meta-seame/recipes-kernel/hailo-pci/hailo-pci_%.bbappend

# Force correct kernel version for compile step
EXTRA_OEMAKE += "KERNELRELEASE=${LINUX_VERSION_EXTENSION}"

# Override do_install: the hailo Makefile's 'make install' calls depmod.sh
# without kernelrelease argument, causing do_install to fail.
# Install the .ko manually instead.
do_install() {
    install -d ${D}${nonarch_base_libdir}/modules/${KERNEL_VERSION}/kernel/drivers/misc/
    install -m 0644 ${S}/hailo_pci.ko \
        ${D}${nonarch_base_libdir}/modules/${KERNEL_VERSION}/kernel/drivers/misc/
}
```

In `agl-image-minimal.bbappend`, the image install references the versioned kernel module package name directly:

```bitbake
# meta-seame/recipes-core/images/agl-image-minimal.bbappend
IMAGE_INSTALL:append = " network-config"
IMAGE_INSTALL:append = " kernel-module-hailo-pci-6.6.63-v8-16k"
IMAGE_INSTALL:append = " kuksa-certs"
IMAGE_INSTALL:append = " can-to-kuksa"
```

> **Note:** The package name includes the kernel version string (`6.6.63-v8-16k`). This is the package name generated by the Yocto `module` class and refers to the actual `.ko` file, even though the kernel has been rebuilt with 4K pages. The package naming reflects the original kernel version extension, not the page size configuration.

### HailoRT userspace installation

HailoRT 4.23.0 userspace (CLI tools, shared library, Python bindings) is installed without pip — ARM64 wheels are downloaded on a host machine and transferred via `scp` due to the RPi5 lacking internet DNS resolution:

```bash
# On host (x86 with internet access)
pip download hailort==4.23.0 --platform linux_aarch64 \
    --only-binary=:all: -d /tmp/hailo-wheels/

# Transfer to device
scp /tmp/hailo-wheels/*.whl root@10.21.220.192:/tmp/

# On device — install from local files
pip install --no-index /tmp/*.whl --break-system-packages
```

### Verifying the driver

After a correct build and boot:

```bash

# Device node present

# Firmware and hardware reachable
hailortcli fw-control identify
```

## Inference Pipeline

### Architecture

The inference pipeline avoids GStreamer's `libcamerasrc` (not available in this AGL build) and uses `rpicam-vid` piping raw MJPEG frames directly to a Python process. Display output is handled by a separate GStreamer pipeline writing to `waylandsink`.

```
rpicam-vid (MJPEG stdout)
        │
        ▼
Python (subprocess pipe)
  ├── MJPEG decode (cv2.imdecode)
  ├── Resize → 640×640
  ├── Hailo-8 inference (hailo_platform)
  │     └── /dev/hailo0 via PCIe
  ├── Bounding box overlay (cv2)
  └── GStreamer appsrc
              │
              ▼
        waylandsink (Wayland/Weston display)
```

> **Note:** The inference script (`yolo_live.py`) is deployed manually to `/data/` on the device via `scp`. It is not part of the Yocto build system.

### Camera capture

`rpicam-vid` streams MJPEG to stdout; Python reads it via a subprocess pipe and decodes each frame:

```python
cam_cmd = [
    "rpicam-vid",
    "--width", "640", "--height", "640",
    "--framerate", "30",
    "--codec", "mjpeg",
    "--timeout", "0",
    "-o", "-"   # write to stdout
]
cam_proc = subprocess.Popen(cam_cmd, stdout=subprocess.PIPE, stderr=subprocess.DEVNULL)
```

### Frame queue — discarding stale frames

Inference on the Hailo-8 takes longer than the camera capture interval. Without a discard mechanism, frames accumulate and the pipeline runs with increasing latency. A dedicated reader thread feeds a `queue(maxsize=1)`, dropping any frame not consumed in time:

```python
import queue, threading

frame_queue = queue.Queue(maxsize=1)

def camera_reader(proc, q):
    buf = b""
    while True:
        chunk = proc.stdout.read(4096)
        if not chunk:
            break
        buf += chunk
        start = buf.find(b"\xff\xd8")
        end   = buf.find(b"\xff\xd9")
        if start != -1 and end != -1 and end > start:
            jpg = buf[start:end+2]
            buf = buf[end+2:]
            try:
                q.put_nowait(jpg)       # drop if queue is full
            except queue.Full:
                pass

threading.Thread(target=camera_reader, args=(cam_proc, frame_queue), daemon=True).start()
```

The main loop pulls the latest frame only:

```python
jpg = frame_queue.get()
frame = cv2.imdecode(np.frombuffer(jpg, dtype=np.uint8), cv2.IMREAD_COLOR)
```

### Hailo inference

The Hailo-8 is initialised once at startup using the `hailo_platform` API:

```python
from hailo_platform import (
    HEF, VDevice, HailoStreamInterface,
    InferVStreams, ConfigureParams,
    InputVStreamParams, OutputVStreamParams, FormatType
)

HEF_PATH = "/data/models/yolov8n.hef"

hef            = HEF(HEF_PATH)
device         = VDevice()
config_params  = ConfigureParams.create_from_hef(hef, interface=HailoStreamInterface.PCIe)
network_group  = device.configure(hef, config_params)[0]
input_params   = InputVStreamParams.make(network_group, format_type=FormatType.UINT8)
output_params  = OutputVStreamParams.make(network_group, format_type=FormatType.FLOAT32)
infer_pipeline = InferVStreams(network_group, input_params, output_params)
active_group   = network_group.activate()
```

Each frame is passed as a dict keyed by the input stream name:

```python
input_data = {hef.get_input_vstream_infos()[0].name: np.expand_dims(frame, axis=0)}

with infer_pipeline as pipeline:
    output = pipeline.infer(input_data)
```

### Display output

The annotated frame is pushed to a GStreamer `appsrc` connected to `waylandsink`. Environment variables must be set before GStreamer initialises:

```python
import os
os.environ["WAYLAND_DISPLAY"] = "/run/wayland-0"
os.environ["XDG_RUNTIME_DIR"] = "/run/user/0"

import gi
gi.require_version('Gst', '1.0')
from gi.repository import Gst, GLib

Gst.init(None)

W, H = 640, 640
out_pipeline = Gst.parse_launch(
    f"appsrc name=src format=time is-live=true "
    f"caps=video/x-raw,format=BGR,width={W},height={H},framerate=30/1 ! "
    f"videoconvert ! "
    f"waylandsink display=/run/wayland-0 sync=false"
)
appsrc = out_pipeline.get_by_name("src")
out_pipeline.set_state(Gst.State.PLAYING)
```

Pushing a processed frame:

```python
result_bytes = annotated_frame.tobytes()
buf = Gst.Buffer.new_wrapped(result_bytes)
appsrc.emit("push-buffer", buf)
```

### Running the pipeline

```bash
WAYLAND_DISPLAY=/run/wayland-0 XDG_RUNTIME_DIR=/run/user/0 \
    python3 /data/yolo_live.py
```

Models are stored at `/data/models/` and can be swapped by changing `HEF_PATH`. The pipeline is model-agnostic as long as the HEF file targets the Hailo-8 and produces YOLO-format output.

## Camera IMX708

### Hardware

The Raspberry Pi Camera Module 3 (IMX708 Wide NoIR variant) connects via the MIPI CSI-2 interface on the RPi5. On AGL, the kernel registers it through the `rp1-cfe` driver:

```bash
v4l2-ctl --list-devices
# rp1-cfe (platform:1f00128000.csi):
#     /dev/video0 ... /dev/video7
```

The camera is accessed via `libcamera` / `rpicam-apps`, not directly via V4L2.

### CMA fix (Yocto build level)

The RPi5 ignores the `cma=` kernel command-line parameter. CMA must be configured via the `vc4-kms-v3d` device tree overlay in `config.txt`. The AGL base layer writes `cma-256` for all targets; this is insufficient for the IMX708 pipeline and must be overridden to `cma-512` for RPi5.

The fix is applied in `rpi-config_git.bbappend` via a `do_deploy:append:raspberrypi5()` function that replaces the overlay line using `sed`:

```bitbake
# meta-seame/recipes-bsp/bootfiles/rpi-config_git.bbappend

# SEA:ME: CAN HAT, Hailo-8 PCIe e camera IMX708

ENABLE_DUAL_CAN_SEED_FD_HAT_V2 = "1"
RASPBERRYPI_CAMERA_V3 = "1"

RPI_EXTRA_CONFIG:append = " \n\
dtparam=pciex1 \n\
dtparam=pciex1_gen=2 \n\
ignore_lcd=0 \n\
"

# Override: substituir cma-256 por cma-512 para suportar camera IMX708 + Hailo-8
do_deploy:append:raspberrypi5() {
    sed -i 's/dtoverlay=vc4-kms-v3d-overlay,cma-256/dtoverlay=vc4-kms-v3d,cma-512/' \
        ${DEPLOYDIR}/bootfiles/config.txt
}
```

This recipe also enables PCIe Gen 2 for the Hailo-8 (`dtparam=pciex1`, `dtparam=pciex1_gen=2`) and enables the Camera Module 3 (`RASPBERRYPI_CAMERA_V3 = "1"`).

### libcamera PiSP support (Yocto build level)

The RPi5 uses the PiSP (Pi Image Signal Processor) camera pipeline, which differs from the VC4 pipeline used by earlier Raspberry Pi models. A `libcamera` bbappend in `meta-seame` overrides the `raspberrypi` PACKAGECONFIG to enable both the VC4 and PiSP pipelines:

```bitbake
# meta-seame/dynamic-layers/multimedia-layer/recipes-multimedia/libcamera/libcamera_%.bbappend

# Override raspberrypi PACKAGECONFIG to add RPi5 PiSP support
PACKAGECONFIG[raspberrypi] = "-Dpipelines=rpi/vc4,rpi/pisp -Dipas=rpi/vc4,rpi/pisp -Dcpp_args=-Wno-unaligned-access"
```

Without this override, `rpicam-apps` cannot initialise the camera on RPi5 because the PiSP pipeline and IPA module are not built.

### IPA proxy symlink fix (Yocto build level)

`rpi-libcamera` installs the IPA proxy binary as:

```
/usr/libexec/libcamera/raspberrypi_ipa_proxy
```

`rpicam-apps` on RPi5 with the `pisp` pipeline expects:

```
/usr/libexec/libcamera/rpi_ipa_proxy
```

Without the symlink, `rpicam-hello` and `rpicam-vid` fail silently or exit immediately. The fix is a bbappend that creates the symlink at install time:

```bitbake
# meta-seame/recipes-camera/rpi-libcamera/rpi-libcamera_%.bbappend
do_install:append() {
    ln -sf raspberrypi_ipa_proxy \
        ${D}${libexecdir}/libcamera/rpi_ipa_proxy
}
```

### Known issues

| Issue | Root cause | Fix |
|-------|------------|-----|
| Camera not detected — `No cameras available` | `rpi_ipa_proxy` symlink missing | Add symlink in `rpi-libcamera_%.bbappend` |
| Camera not detected on RPi5 | PiSP pipeline not built in libcamera | Add `libcamera_%.bbappend` with PiSP PACKAGECONFIG |
| `ERROR: vc4-kms-v3d ... unable to allocate` | CMA too small (`cma-256`) | Override to `cma-512` via `do_deploy:append:raspberrypi5()` |
| `imx708_wide_noir: No static properties` warning | Sensor not in libcamera properties database | Cosmetic warning only — camera functions normally |
| `rpicam-apps` exits immediately without output | Wrong `WAYLAND_DISPLAY` or missing `XDG_RUNTIME_DIR` | Set both env vars before launching |
